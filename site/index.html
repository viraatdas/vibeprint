The sketch is the spec.

Draw your system on an iPad. Claude Code or Codex reads it, proposes changes in its own blue pen, and checks off each part as it gets built. Your ink is never touched.

Black is yours. Blue is the agent's, and dashed blue is waiting on you.

Start in your repo

Vibeprint runs on your laptop next to your code. The iPad joins over Wi-Fi by scanning the QR code it prints. There's no account and nothing hosted.

Needs Node 20 or newer. init adds the agent rule to AGENTS.md and connects Claude Code. For Codex, run codex mcp add vibeprint -- vibeprint mcp.

# once
npm install -g vibeprint

# in your project
vibeprint init
vibeprint

How a session goes

  1. Sketch, then submit

    Boxes, arrows and words with the Pencil. Tap Submit when it says what you mean.

  2. The agent reads it

    Faint tags show what it understood. If one is wrong, scribble a correction and submit again.

  3. It proposes, you decide

    Changes arrive as small batches of marks. Accept them all with one tap, or go through them one by one.

  4. The build shows up

    As code lands, the agent marks each part building, done or blocked, right on your boxes.

How the agent draws

Every agent action is a mark with an author and a status, kept apart from your ink.

  • Always in its own color. You can tell its ink from yours at a glance, and hide all of it with one button.
  • Never on your strokes. It adds beside, strikes through, or writes a correction next to yours. An accepted strike dims your shape and doesn't delete it.
  • Waits for your pen. Marks only appear after you've paused, one at a time, drawn on like a second pen.
  • A few at a time. Proposals come in short batches with a one-line summary, never a wall of edits.
  • Asks in the margin. Questions are notes pinned beside a shape. Answer by writing next to them.
  • Quiet by default. Tags stay faint, and progress marks are a dashed outline turning solid with a check.

Works with the agent you already use

One MCP server serves Claude Code and Codex alike. init puts this rule where both of them read it:

Read the architecture through the Vibeprint tools before starting work. If the build needs a structural change, propose it as a mark and wait for approval. Never deviate silently.

Lives in your repo

The graph, the marks and your drawing are plain JSON in .vibeprint/, committed alongside your code. The spec has history, shows up in diffs, and travels with every clone.

Handwriting is read by Claude when ANTHROPIC_API_KEY is set. Without it, your coding agent does the reading through the same tools, with whatever model it runs on.
